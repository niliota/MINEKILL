# Bridge contract

Two games, one world. **Minecraft is the simulation engine; ULTRAKILL is the host: the world,
the renderer, the camera and the window.** This file defines who owns what and every channel
between them. Check changes against it.

## Route

Live state exchange. Real Minecraft runs as a real client (with its integrated server); real
ULTRAKILL runs as the host. A Fabric mod and a BepInEx plugin exchange state through
memory-mapped files. **No images cross**: no frames, no depth, no compositing. Everything
Minecraft shows is rebuilt from its own data and drawn natively by ULTRAKILL.

## Versions

| | |
|---|---|
| Host | ULTRAKILL (Steam), Unity 2022.3.29f1, Mono, x86-64 |
| Host loader | BepInEx 5.4.23.2 win_x64 |
| Guest | Minecraft 26.3, Fabric Loader 0.19.5, Java 25 (no Fabric API) |
| Platforms | Linux: Minecraft native + ULTRAKILL under Wine (tested). Windows: both native (untested). |

## Ownership

| Thing | Owner | Notes |
|---|---|---|
| Player position, physics, health, hunger, death | **Minecraft** | ULTRAKILL's player is a kinematic puppet placed from Minecraft's position every frame. |
| ULTRAKILL movement, weapons, fists, HUD | **switched off** | `NewMovement` deactivated, `GunControl.NoWeapon()`, weapon HUD and crosshair hidden, re-asserted every frame. The user decided against any ULTRAKILL movement (no dash, no slide). |
| Camera | **ULTRAKILL**, aimed by Minecraft | Mouse delta goes to Minecraft, which turns its player; ULTRAKILL copies the resulting yaw/pitch and puts its camera at Minecraft's eye (feet + eye height), so the view is exactly Minecraft's crosshair ray. F5 moves it behind/in front at Minecraft's camera distance. |
| Level geometry | **ULTRAKILL** | Rendered and collided by ULTRAKILL. Not mineable. |
| Minecraft blocks, fluids, entities, block entities | **Minecraft** | Simulated by Minecraft, drawn by ULTRAKILL (meshes, models, textures streamed). The Minecraft world is a void; blocks exist where the player puts them. |
| Collision of ULTRAKILL geometry for Minecraft | **ULTRAKILL shapes, resolved by Minecraft** | ULTRAKILL publishes boxes (exact axis-aligned boxes + a 1/8-block voxel field for everything else) around the player and around clusters of other entities. Minecraft uses them in entity collision, pathfinding, fluid flow, projectile traces, aiming (picking, buckets). |
| Collision of Minecraft blocks for ULTRAKILL enemies | **not built** | |
| ULTRAKILL enemies | **ULTRAKILL** | Untouched. They do not yet interact with the Minecraft player or mobs. |
| Inventory, mining, placing, items, saves | **Minecraft** | Placing onto ULTRAKILL surfaces goes through a custom pick (`UkPick`) against ULTRAKILL's boxes. |
| GUI | **Minecraft**, drawn by ULTRAKILL | Minecraft lays its GUI out for ULTRAKILL's screen size; every GUI quad is captured and replayed. Keys and mouse go to an open Minecraft screen. |
| Pause | both | ULTRAKILL's Esc menu is ULTRAKILL's. Minecraft's pause menu (backtick) freezes ULTRAKILL's time too. |

## Units and axes

- **Scale:** 1.94445 ULTRAKILL units per block, measured from ULTRAKILL's 3.5-unit player
  capsule against Minecraft's 1.8-block player.
- **Mapping:** relative and anchored. At each level load, Minecraft's spawn position is pinned to
  the floor under ULTRAKILL's spawn; afterwards only deltas apply. Horizontally the map is a fixed
  linear map from both games' bases, cached at the anchor (in practice an X mirror,
  `diag(-1, 1)`); vertically a plain scale. No term depends on the current yaw.
- **Angles:** `CameraController.rotationY = wrap(mcYaw)`, `rotationX = -mcPitch`. Minecraft yaw
  is unbounded; ULTRAKILL clamps, so the yaw is wrapped.
- **Time:** Minecraft ticks at 20 Hz but publishes per frame (interpolated); ULTRAKILL runs at
  its own frame rate.

## Channels

Layout, offsets and field docs: `bridge/protocol/PROTOCOL.md`, generated by
`bridge/protocol/generate.py` (the only source of truth) and verified by `check-layout.sh`.

**`minekill.bridge`** (fixed layout, ~3.3 MB)

| Region | Direction | Content |
|---|---|---|
| header | both | magic, layout fingerprint, pids, heartbeats, spawn request, flags, drop counters |
| `PLAYER` slot | MC → UK | position, velocity, yaw/pitch, movement state, health/food/air, spawn acknowledgement |
| `CAMERA` slot | MC → UK | yaw, pitch, FOV, eye height, perspective (F5), camera distance |
| `INPUT` slot | UK → MC | held keys, mouse delta, buttons, hotbar, scroll, screen size, cursor |
| `SELECTION` slot | MC → UK | the targeted block outline / placement box |
| `CORRECTION`, `LEVEL` slots | UK → MC | reserved, unused |
| `MC_EVENTS` ring | MC → UK | reserved |
| `UK_EVENTS` ring | UK → MC | key presses (SDL scancode + keycode + modifiers), typed characters, extra mouse buttons |
| `COLLISION` table | UK → MC | up to 16384 boxes in block coordinates, with the mapping generation |
| `COLLISION_INTEREST` table | MC → UK | up to 128 entity-cluster centres to publish collision around |
| `GUI` table | MC → UK | every GUI quad this frame, screen state, GUI scale |
| `HAND` table | MC → UK | first-person hand/item quads in view space, hand FOV |
| `WORLD_MODELS` table | MC → UK | entity, block-entity and crack quads in block coordinates |
| `PARTICLES` table | MC → UK | live block particles |

Slots and tables are seqlocked snapshots (latest wins, torn reads retried). Rings drop the newest
event when full and count it.

**`minekill.stream`** (64 MB single-producer ring, MC → UK): block atlas, item and GUI atlases,
GUI sprite rectangles, section meshes (per 16³ section, removal = 0 vertices), dynamic texture
mirrors (font sheets, standalone GUI textures, skins, other atlases) and animated-sprite frame
patches. ULTRAKILL requests a full resend after (re)connecting.

**Paths:** Linux `/var/tmp/minekill.bridge` = `Z:\var\tmp\minekill.bridge` in Wine; Windows
`%LOCALAPPDATA%\MINEKILL\minekill.bridge` on both sides. `MINEKILL_BRIDGE` overrides it.

## Lifecycle

- **Start order:** either. Whoever opens second completes the handshake.
- **Layout changes:** the header's version is a fingerprint of the whole layout. A file laid out
  by another build is wiped and re-laid by whichever side opens it, never interpreted.
- **Liveness:** each side advances an epoch-millisecond heartbeat; a side whose heartbeat is
  older than 2 s is treated as gone. A non-zero pid alone means nothing (a killed game leaves it).
- **Focus:** neither game may stop when unfocused. ULTRAKILL forces `runInBackground`; Minecraft
  is told it is focused while ULTRAKILL is connected, its cursor grab is suppressed and its AFK
  frame limiter is held off.
- **Level load (UK):** ULTRAKILL raises a spawn request; Minecraft teleports its player to
  (1000.5, 128, 1000.5), zeroes velocity, holds it and acknowledges; ULTRAKILL then anchors
  (feet on the floor under its spawn). The hold ends on the first movement key. Falling below the
  world floor returns the player to spawn instead of killing it.
- **ULTRAKILL gone:** Minecraft releases any hold, drops all ULTRAKILL collision and stops
  publishing GUI/world data; it plays as plain Minecraft.
- **Minecraft gone:** stale tables are ignored after 2 s; ULTRAKILL keeps running.

## Not covered

- Combat between Minecraft and ULTRAKILL (either direction) and ULTRAKILL enemies colliding with
  Minecraft blocks.
- Multiplayer. Both games are used single-player only.
- ULTRAKILL's own systems beyond the switches listed above are unmodified.

## Environment facts that cost time

- A BepInEx 5 plugin class must derive from `BaseUnityPlugin`; a `MonoBehaviour` is skipped
  silently ("0 plugins to load").
- BepInEx's plugin GameObject is destroyed by ULTRAKILL's first scene change; the plugin hosts
  itself on a `HideFlags.HideAndDontSave` object.
- Under Wine/Mono, never hold a second `FileStream` across `MemoryMappedFile.CreateFromFile`. On
  native Windows the opposite is needed: open the file shared and map through that handle
  (`Platform.MapShared`).
- Detect Wine with ntdll's `wine_get_version` export, not with the presence of `Z:`.
- `Application.isFocused` is unreliable under Wine; do not gate on it.
- ULTRAKILL reads look input through the Input System (`Pointer.current.delta`); legacy
  `Input.mousePosition` freezes while the cursor is locked.
- Minecraft 26.3 is unobfuscated and its input is **SDL3**: key events carry an SDL scancode
  (bindings) and an SDL keycode (text editing); mouse buttons are SDL numbers (1 left, 2 middle,
  3 right). Input entry points reject window handle 0.
- Mixin targets must be checked against the 26.3 bytecode (`javap -p`): an inherited method
  is not a target on the subclass, and a missing target crashes Minecraft at load.
- ULTRAKILL's `ULTRAKILL/Master` shader has no cutoff property; alpha testing exists only as
  compiled variants (`ALPHA_TEST`), and not every keyword combination is compiled.
- The process id ULTRAKILL reports under Wine is a Wine pid, not a Linux one.
- `pkill -f ULTRAKILL.exe` kills the calling shell; kill by exact pid (`pgrep -x`).
